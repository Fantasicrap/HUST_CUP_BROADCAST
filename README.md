# HUST_CUP_BROADCAST

本地运行的足球 OBS 浏览器源图文包装，提供 PULSE「几何竞技」与 NOCTURNE「蓝夜杯赛」两套主题。当前 **v0.2.1-startup-fix** 修复 Windows 启动脚本闪退；v0.2 的七项修订和两套主题均保留。

原版已保存在私有仓库 [Fantasicrap/HUST_CUP_BROADCAST](https://github.com/Fantasicrap/HUST_CUP_BROADCAST) 的 `v0.1.0-preview` 标签。本次修订的本地代码与原标签分别保留；上传情况以实际发布记录为准。

## 启动与 OBS

需要 Node.js 20 或更新版本。无需 npm install，无运行时第三方包，不需联网加载素材。

完整解压后双击 `启动预览.cmd`。等待窗口显示 `[READY]` 后会自动打开网页，**保持服务窗口打开**。失败时窗口会保留，日志在 `runtime/startup.log`。也可在本目录执行：

```powershell
node server.mjs
```

- 中文后台：<http://127.0.0.1:3210/>
- **OBS 正式合成输出**：<http://127.0.0.1:3210/overlay.html?mode=live&transparent=1>
- 独立草稿预览例：<http://127.0.0.1:3210/overlay.html?scene=formation>

OBS 添加浏览器源，宽 1920、高 1080，置于比赛视频上方。需要动画时可设置 60fps。OBS 必须使用带 `mode=live` 的地址，后台内部预览不会直接播出。

遇到双击闪退、Node 未找到或端口占用，见 [Windows 启动说明](docs/Windows-startup.md)。新启动器不修改安全中心或系统执行策略。

若端口占用，停止旧版服务后重新启动；也可设置 `$env:PORT='3211'` 再运行 `node server.mjs`，并将所有地址中的端口改成 3211。不要同时运行两个服务写同一份存档。按 Ctrl+C 停止。

## 当前可操作功能

1. **每个模块独立采用**：左上比分、进球、换人、开场、首发、替补、点球简版/结果、底部比分分别开关；逐线、翻转、照片、视频、黄牌、队长、替补衔接也可独立选择。
2. **紧凑图形**：常驻比分为 782×62 单行，赛事 logo 居于两队名之间；进球约 600×92，换人约 600×120。
3. **自定义素材与比分**：双方队徽、赛事 logo 上传；主客队比分 ±1；球衣颜色与门将颜色、单人颜色可分别设置。
4. **放大阵容与逐线翻牌**：右侧 1364×754；门将→后卫→中场→前锋，球衣翻至照片或静音视频，回到阵型后保留照片；未上传对应素材时保留球衣。
5. **同尺寸替补**：完整阵容后可翻至同一区域的替补名单；姓名、号码、括号内自定义位置、累计黄牌和队长可显示。替补也可以单独播出。
6. **点球简版**：底部居中 820×131；保留大结果面板。点球数据独立，支持先罚、罚进/失、待罚、修改、撤销、重罚与确认结束；超过 8 轮展示最近轮次窗口。
7. **底部比分与恢复**：开场、半场、下半场开场、全场、进球后开球可独立触发；半场/全场上展进球记录，进球后显示最后一条有效进球；默认 5.5 秒后回左上。
8. **草稿与实播分离**：编辑、上传、±1 和预览先保存草稿；点击正式播出或应用资料才更新 OBS。清屏取消当前流程；输出刷新/重连按时间位置恢复，不从头再播。

照片与视频可分别上传：照片用于最终阵型，视频用于逐线媒体展示。只有视频、没有照片时，回到阵型仍用球衣；这是有意的降级处理。上传失败或缺失素材都有替代图形。所有球员视频强制静音。

## 操作顺序

1. 在「每个部分独立启用」选择所需模块与场景。
2. 在「比分、球队与 logo」设置队名、简称、队徽、赛事图形、球衣色和比分。
3. 在「首发、逐线翻牌与替补」选择球队，编辑名单、黄牌、队长，上传照片/视频。位置从下拉建议选择或输入自定义文字。
4. 左侧选「首发阵型」，动画检查选择「自动播放完整流程」，点击「仅重播预览」检查。可以取消某一线、关闭翻转或取消替补衔接。拖动球员仅在阵型预览可用。
5. 满意后点击「正式播出当前模块」。**应用资料到实播**只更新数据，保留当前动画时间位置；**正式播出**启动一次新的播放。
6. 用底部场景选择器触发简要比分牌。半场比分单独录入；半场进球记录只取上半场，完场取全部有效记录。最后一条进球来自进球记录，不是仅编辑的进球弹窗。
7. 紧急清屏立即撤下全部图形；恢复按钮重新显示左上比分（该模块须已启用）。

完整说明见 [v0.2 修订说明](docs/v0.2修订说明.md)。

## 资料保存与素材

- `runtime/state.json`：草稿与实播快照，按版本保存，通过临时文件替换；服务重启后读取。
- `runtime/assets/`：上传素材，使用内容哈希文件名；HTTP 地址是相对的 `uploads/...`，无绝对电脑路径。
- 换电脑请复制项目代码和完整 `runtime/` 目录。源码 ZIP 默认不含个人上传和运行状态；不能只复制 JSON 而遗漏素材。
- 图片支持 PNG/JPG/WebP/安全 SVG（最大 12 MB），视频支持 MP4/WebM（最大 100 MB）。编解码能否播放仍取决于浏览器；推荐先在后台实际预览。
- 头像示例为原创非真人剪影，点击「填充原创演示剪影」可检查最终阵容。不是球员真实照片。

## 仍待完成的原始核心范围

本次是可操作的修订评审版，尚未交付完整整场比赛系统。真实时间戳比赛时钟与完整阶段、自定义赛制、给牌业务与人数、多人换人实际场上名单、通用事件队列与优先级、两回合、全部开场/半场/总结模块、统计人物、VAR、回放转场、统一输出延迟、快捷键和完整导入导出仍需后续开发。

当前显示时间可编辑但不会真实计时；换人条不修改场上名单；累计黄牌是人工资料，不等同于自动判两黄变红。已实现的进球记录与 ±1 只是本版操作，不代表原始完整事务日志已完成。未进行 OBS 实机或持续 60fps 推流性能验收。
