# v2.0.0 换人名额、窗口与脑震荡换人

日期：2026-10-23。此版同时包含 v1.9.0 后续检查发现的全项目逻辑修复。

## 赛前设置

进入「赛前准备 → 资料 → 比赛人数与换人制度」，新项目默认启用每队 **5个普通换人名额、3个普通换人窗口**。两个数字均可修改，允许0；若赛事不限次数，可关闭普通换人限制。脑震荡规则默认关闭，按赛事需要勾选。

填写后，在「阵容」步骤点「将已编辑阵容同步到比赛」，再预览并发布资料。单纯编辑不改变已经执行的比赛制度。开赛或已有事件后不能修改制度；先导出备份，设置新赛事规则，再明确新建比赛。新建比赛沿用当前赛前配置。

旧项目包和旧 runtime 保留原来的无限制制度，不会因为升级追溯处罚或阻止历史换人。赛前表单仍提供3窗口、5名额作为填写默认值。

## 赛中操作

打开「赛中 → 换人」，选择球队、换下与换上球员，并选择本组类型：

- **普通换人**：消耗普通名额；同一批次多人共用一个普通窗口。
- **脑震荡换人**：仅在启用政策后可选；每队本场最多1名，不消耗普通名额和窗口。应用成功才为对方赠送1个专项额外名额和窗口。被换下者不得再次上场，循环换人也不例外。
- **对方脑震荡赠送换人**：收到赠送后才可选，消耗专项额度，普通额度不变；赠送窗口不能拿来安排普通换人。

一批可添加多组、混合不同类型；每组按添加时的类型保存。全部填写后「确认并预览 → 应用并播出」。预览不扣额度、不改名单，动画重播也不重复扣减。

同一次实际比赛暂停如分批录入，可选择「沿用本队上个窗口」；不能跨暂停沿用。系统会保存明确的窗口关联，跨阶段不能沿用，撤销窗口来源时也会检查后续依赖。

普通与赠送换人同批使用普通窗口时，不额外扣专项窗口；脑震荡与普通换人同批时，普通换人仍须扣正常名额和窗口。

## 中场换人

以实际比赛阶段为准：**上半场结束并应用「中场」后，到应用「下半场」开球前**，普通换人扣名额，不扣窗口。只是按「暂停」或切到左侧中场页面，不等于比赛已进入中场。

加时前休息和加时中场同样免窗口，名额仍计算。下半场一旦正式应用开球，新的普通换人恢复计算窗口。系统不会因为时间到45分钟或暂停计时自动免窗口。

已验证中场换人：当前场上名单正确更新，最初首发保持原样，计时保持暂停，左上比分牌保持隐藏，左下换人条正常播出。

## 左下角扩展条

原紧凑换人条下方增加约36像素高的额度区域，同一行显示本队当前剩余普通名额与普通窗口。

示例：**剩余名额 3（+1） · 换人窗口 1（+1）**，表示还有3个普通名额、1个普通窗口，另有各1个未使用的赠送额度；不是把额外名额重复计入普通数字。

仅勾选政策、尚未实际使用脑震荡换人时，不显示任何括号，也不显示「（+0）」。只有获赠的一方显示「（+1）」。使用后，对应名额或窗口的括号会分别减少；休息时使用专项名额仍免窗口，因此两个数字分别核算。

主体先竖线停顿、向右展开，停稳后再向下展开额度区；退场先收额度，再收回竖线。两套主题均保持原紧凑宽度与透明背景。

## 日志、纠错和恢复

日志支持「修正类型／发生时段」，可修正每组类型和真实发生阶段；修改后从同一账本重算名单、窗口及赠送额度。撤销也会重算。若对方已经使用赠送额度，不能直接删除其脑震荡来源，须先撤销或修正依赖记录。已有后续换人依赖被换上者时，同样先处理后续关联。

规则、每组类型、实际发生阶段和沿用窗口关联随项目导出。导入和服务恢复后额度会从有效事件重新计算，不靠浏览器临时计数，不因刷新或重播重复扣减。

## 验证与使用边界

74项 Node 测试通过，包含新增规则、双方对称脑震荡赠送、普通额度耗尽、中场与加时休息、沿用窗口与撤销依赖、循环换人、特殊替补回场、旧包/旧runtime迁移。8套57组当前浏览器回归通过，包括9组新换人界面、动画与真实输出检查，浏览器错误为空。证据见[验证摘要](验收/v2.0.0.json)。

运行 `npm test`、`npm run check`、`npm run review`；单独验收本模块用 `npm run review:substitutions`。所有验收使用独立临时比赛。

规则实现参考 [IFAB 永久脑震荡换人协议](https://theifab.com/laws/latest/additional-permanent-concussion-substitutions-protocol/)。实际换人类型由操作员依据赛事和裁判决定录入，系统不判断球员是否发生脑震荡。此版不会自动增加其他加时赛普通名额，仍以赛前配置为准。

此版包含服务端变更，需择时重启并刷新后台/OBS源生效。本次开发未重启真实比赛服务，也未改写正式比赛数据；升级前先导出备份，恢复时按既有计时提示处理。
