# HUST_CUP_BROADCAST 项目介绍

HUST_CUP_BROADCAST 是供校园足球赛事使用的本地直播图文包装系统。操作员在中文后台管理比赛资料、计时、事件和播出队列，OBS 通过浏览器源把透明图形叠加到比赛视频上。当前版本为 **v2.0.0**，原作者为 **Fantasticrap@GitHub**。

系统覆盖赛前入场、比赛进行、中场、加时与点球、赛后总结。PULSE 与 NOCTURNE 两套主题使用同一份比赛数据，可以选择所需模块、方角或圆角、实色或渐变材质。默认采用本地优设标题黑和蓝白配色，渐变也可跟随双方本场球衣色。

## 一名操作员如何完成整场比赛

1. **赛前准备**：按资料、阵容、画面、开播四步填写；同步名单与规则，再核对并发布资料。照片、视频、裁判、解说、赞助均可按需使用。
2. **赛前播出**：预览并播放赛事开场、对阵、入场条、首发名单、阵型及人员介绍。模块可独立触发，也可加入顺播。
3. **比赛进行**：明确应用比赛阶段开表；发生事件时点击事件名称，检索球员、填写、确认预览，再应用并播出。已有记录重播动画不会再次记账。
4. **中场与加时**：实际吹停后明确停表并切换阶段，再核对比分、统计与换人。页面导航本身不改变比赛阶段。
5. **赛后收尾**：核对有效账本，人工确认胜者、晋级或冠军，播出赛果并导出含引用素材的比赛包。

## 已实现的包装与比赛控制

| 范围 | 当前功能 |
|---|---|
| 常驻比分 | 紧凑单行双方队名、队徽、中央赛事logo、比分与计时；可交换logo和时间位置；补时在计时器右侧，球队事件在相应队伍下方展开，最多4张半露红牌 |
| 计时与阶段 | 赛前、上下半场、中场、加时各阶段、点球、结束与中断；自定义时长；应用、暂停、正负校准和确认清零；到时不自动结束 |
| 赛前阵容 | 5/7/8/9/11人制，首发人数匹配且含1名门将，替补最多16人；对应预设和自定义分线、拖动位置、队长、累计黄牌、照片及静音视频 |
| 阵容动效 | 双方独立或翻转衔接；逐线从左到右放大、翻牌媒体、窗帘收起、回到照片阵型；可衔接同尺寸替补名单 |
| 比赛事件 | 进球、取消进球、黄牌、红牌、两黄变红、多人换人、点球判罚/罚失、VAR和通知；支持原因、关联给牌、纠错与重播 |
| 换人额度 | 新项目默认每队5名额、3窗口；赛前可改或关闭普通限制；中场扣名额免窗口；可选脑震荡与对方专项赠送，左下显示剩余额度 |
| 底部比分 | 开场、半场、下半场开球、进球后开球、全场五类简版；按场景显示进球人员，休息与结束阶段隐藏左上 |
| 点球大战 | 独立比分、先罚队、罚进/罚失/重罚、提前决胜、突然死亡、长轮次布局；进行中简版及赛后大面板，结束须人工确认 |
| 半场与赛后 | 比分、有效进球与OG/P标记、总比分、点球结果、统计与可选最佳球员；赛果须确认 |
| 辅助包装 | 裁判与解说独立、可选备注、通用人物条、赞助logo、回放角标及图形转场 |
| 独立二路 | 单独进球动画和API，球衣跟队色、GOAL与姓名闪动、足球入网；只播动画，不记分、不切主路 |

所有展开类动效均包含退出过程。左下包装先出现竖线、停顿、向右展开；居中包装从中心向两侧展开，停顿后再展开附加区；退场反向执行。紧急清屏立即撤下全部包装并清除队列，比赛计时与账本保留。

## v2.0.0 的换人规则

普通多人换人可一次填写多组，确认后整批记账，播出逐组展示。同批普通换人按人数扣名额、共用一个窗口；同一实际暂停分批录入可明确沿用窗口，不能跨暂停或跨阶段借用。

启用脑震荡政策后，每队最多使用1次永久脑震荡换人，不扣普通名额或窗口，并给对方增加1个专项名额和窗口。对方实际获赠后，才能选择赠送换人；未发生赠送时，画面不显示括号。示例“剩余名额 3（+1）”代表3个普通名额另加1个专项额度。

中场是否免窗口，以计时区实际阶段为准。只打开中场页面或暂停上半场计时不算进入中场。规则、名单、余额从账本统一重算；重播、撤销、纠错、导入和重连保持一致。旧存档保留原无限制制度，不追溯新增限制。

[详细规则与示例](v2.0.0换人名额与窗口.md)

## 资料 预览 与实播的关系

**同步名单**建立赛中检索和记账依据；**发布资料（不换画面）**发布队名、素材、配色等草稿，不开始动画；**预览此画面**只检查包装；**正式播出此画面**才送入输出。比赛事件通过弹窗的“确认并预览 → 应用并播出”完成记账与播放。

比分校正不会补出进球者。乌龙球选择球员所属队、给对方加分，记录及播报保留在乌龙方；输出统一使用(OG)和(P)。VAR图文不代替撤销账本操作。未知统计留空，不会用零假装已知数据。

## 本地运行与 OBS 接入

需要 Node.js 20 或更新版本。完整下载源码并解压，双击“启动系统.cmd”，看到 READY 后保持窗口打开；正常核心播出不需要 npm install，也不依赖网络字体或CDN。

| 用途 | 默认地址 |
|---|---|
| 中文后台 | http://127.0.0.1:3210/ |
| OBS合成输出 | http://127.0.0.1:3210/overlay.html?mode=live&transparent=1 |
| 独立二路 | http://127.0.0.1:3210/goal2.html |
| 图形转场 | http://127.0.0.1:3210/transition.html |

浏览器源尺寸为1920×1080，放在视频上方，动画以60fps为目标。常驻和临时层可选择独立地址；主路和二路共用统一输出延迟。源刷新或重连恢复当前有效状态，不从头播放过期事件。

比赛存于 runtime，导出包可携带账本与引用素材。服务恢复时清除旧队列，原运行计时进入暂停恢复流程，由操作员核对并选择离线时间处理。升级前先导出并备份；v2.0.0含服务端改动，需择时重启，再刷新后台和OBS源。

## 可选能力与实际边界

- 本地人像抠图是赛前可选步骤，需另装Python环境与模型；不用抠图仍能运行全部核心播出。已确认的透明照片可随项目导出。
- 回放转场只负责图形遮挡；视频的录制、选择、播放与推流由OBS或外部系统负责。
- 二路提供独立图形地址与接口；多路视频推流仍由OBS安排。
- GIF/WebM是预览素材，正式输出使用实时浏览器源。实际流畅度与资源占用需要在目标OBS电脑实测。
- 5人制净比赛时间、红牌补人、其他赛事特殊规则及额外加时赛名额，不会因人数选择自动执行。
- 积分榜、其他场次和下一场预告属于后续扩展，不作为当前已交付功能宣传。
