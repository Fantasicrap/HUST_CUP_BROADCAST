# v1.9.0 后续逻辑检查（随 v2.0.0 交付）

日期：2026-10-23（UTC+8）。本次检查使用独立临时比赛、随机端口和虚构素材，未重启或改写正式 runtime 比赛。保留两套主题、原版字体和现有版式。

## 已修复的问题

| 问题与触发方式 | 修复后的行为 |
|---|---|
| 修改球队或名单后立即操作计时，控制操作刷新草稿时可能覆盖尚未保存的输入 | 比赛控制操作先等待草稿保存；导入与载入演示也先结束旧的自动保存，避免旧草稿覆盖导入结果 |
| 主路或二路确认预览尚在加载时继续修改字段，旧响应可能重新启用应用按钮 | 确认请求绑定表单版本，内容改变或弹窗关闭后旧响应失效；主路同时核对比赛修订 |
| 换人预览后增删组合，旧的确认仍可使用 | 添加或移除换人组合立即取消原确认，必须再次预览 |
| 中场补记默认归入下半场，临时中断记录的分钟可能丢失补时语义 | 中场默认归上半场，中断沿用原比赛阶段；加时休息与全场补记沿用相应比赛阶段，仍可手工指定所属半场 |
| 直接选择「明确两黄变红」，未单记第一黄时累计黄牌只增加一张 | 本场黄牌与累计黄牌按实际补足的黄牌数增加；罚下人数规则保持原逻辑 |
| 只想调整输出延迟，却同时发布其他未完成的草稿，甚至因未完成阵容而无法调整 | 新增独立的延迟操作，只更新延迟；队名、名单、素材和比分不借此发布 |
| 连续二路播出时，新动画仍在等待延迟，上一条却提前消失 | 二路保留输出时间线，在延迟切换时点前继续原动画；清屏仍立即生效 |
| 模块已关闭并发布，输出渲染仍可能因未到过期时间而强制显示原模块 | 输出统一遵守模块开关、场景开关和实际过期时间，不再用重复的过期分支绕过模块关闭 |
| 明确设置的停留时间与后台实播状态不一致，默认时长之后可能密集重绘 | 输出、监看和日志共用实际 expiresAt；去掉默认时长到点后的无意义快速重绘 |
| 一批多组换人总时长不足，后面的组合来不及显示 | 整批一次记账、一次送播，按添加顺序逐组显示；总时长至少组数×1.2秒，每组同时显示换下和换上 |
| 关闭某个底部场景后，开场顺播仍包含该项，导致整批请求被拒绝 | 顺播过滤关闭的底部场景及禁用的 VAR；保留其他启用模块 |
| 二路、人数制、抠图等检查仍按旧后台位置点击；逐帧检查强制依赖录像组件 | 检查适配赛前四步和二路折叠区；同步检查等待实际事务响应；录像改为可选，逐帧几何检查保持完整 |

未自动改写历史事件的所属半场；历史补记若原来选错，仍需操作员核对处理。本次不把图形转场当作视频回放，也不改变结果须人工确认的规则。

## 接口变化与兼容

POST /api/live 增加 `{ "action": "delay", "delayMs": 1200 }`，范围0–120000毫秒，只更新统一延迟，保留其他已发布资料。原 update 发布操作保留。

GET /api/goal2/state 保留 run、serverNow、last，新增 pending（待延迟切换的动画或 null）。有旧动画仍在播出时 run 返回旧动画，达到新动画的切换时间后再替换。调用方应以 serverNow 与 run.startedAt 判断实际可见时间。

存档格式不变，旧的裁判 College 字段继续兼容、界面称为备注。计时增加 lastPlayingPhase 用于结束后补记的阶段归属；缺少此字段的旧档继续可恢复。

## 升级与验证边界

此版包含服务端修复，需在合适时机停止并重新启动本地服务，再刷新后台与 OBS 浏览器源。比赛进行中应先导出备份，按既有恢复提示选择暂停或补计离线时间。本次检查没有擅自停止正式服务。

上述检查针对本机 Node 与 Edge 的功能、数据和渲染。真实 OBS 推流时的60fps、视频解码、音频权限、长时间运行资源占用仍需在目标设备进行实测；本次未宣称已完成这些设备级验收。可选录像未在本轮重新生成，历史 WebM、GIF和Word均保留。
