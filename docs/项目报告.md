# HUST_CUP_BROADCAST 项目报告

日期：2026-10-19（UTC+8），当前版本：v1.4.3（v1.0功能基线及后续修订均保留）。公开仓库：https://github.com/Fantasicrap/HUST_CUP_BROADCAST 。旧版 v0.1、v0.2、v0.2.1 标签保留，当前新增完整比赛控制能力与统一蓝色视觉。

## 目标与交付

本系统以本地 Node.js 服务、中文控制后台和 OBS 透明浏览器源提供整场足球图文包装。v1.0 已实现原始核心模块；不把图形转场等同视频回放，也不把浏览器自动化等同 OBS 实机性能验收。

完整源代码、Windows 双击启动器、两套同功能主题、中文文档、示例队徽/剪影/球队/名单、可导入完整比赛存档、实际浏览器设计截图及验收脚本均在项目中。运行仅需 Node.js 20+，不依赖 npm 安装和在线素材。开发验收可使用 Playwright 与 sharp。

## 视觉实现

采用用户指定 #85C9FC、#86EFFC、#4E60FC、#1355FC、纯白，辅以深蓝明暗色；红黄牌使用必要的足球语义色。PULSE 为白面几何和竞技蓝，NOCTURNE 为深蓝渐变和光弧。全套共用渲染组件。

用户未提供原字体名，授权使用接近的开源粗黑字体。默认本地 Noto Sans CJK SC Black，OFL 许可证随附；中文与英文共用字面。可上传自有授权字体、队徽、赛事logo、球员照片/静音视频。

保留七项明确修订：各部分独立开关；紧凑左下事件；单行中央logo比分牌及±1；放大右侧阵容、球衣颜色、队长/黄牌并存和逐线翻牌照片/视频；同尺寸替补；底部点球进行中简版；五场景底部比分与5–6秒后恢复常驻。

## 架构

- public/match.js：确定性比赛模型，时间戳时钟、阶段、事件账本、红黄牌、换人、比分/有效进球、点球和赛制。deriveMatch 从原始首发与有效事件重建当前状态，撤销和纠错检查依赖。
- public/model.js：草稿规范化、模块开关、媒体路径、逐线翻牌时间线、底部比分筛选、主题配置。
- server.mjs：本地接口、串行修改、原子文件替换、SSE、素材哈希校验、延迟历史时间线、优先队列、存档恢复和项目导入导出。
- public/graphics.js：纯渲染，按服务时间定位动画，不记账；正式输出不读取草稿。事件刷新按已过时间定位，过期不重播。
- public/preview.js 与 desk.js：资料编辑、预览与直播分离，中文比赛控制、队列、点球、统计、赛制、恢复、移机。
- identity.css 与 desk.css：五色主题、开源字体和新增全部模块；原主题布局扩展而非弃用。

三类状态分别保存：草稿资料、比赛事实账本、当前/等待播出。事件预览在克隆账本中执行，重播仅生成cue，不增加事件。明确记账操作更新比赛，明确播出操作进入直播；普通资料编辑不改变正式画面。

## 重要规则

本场累计黄牌与赛前累计黄牌分开；替补和教练被罚不减少场上人数。换人保留最初首发，当前名单独立重建。进球取消同时影响比分、进球者、赛果和待播旧进球。依赖记录不允许被破坏，先撤销后续关联。

点球大战与比赛进球完全分开；计算满足决胜条件后仍待人工确认。总比分与本场分开，客场进球默认关闭。结果对象必须人工确认；比分/事件/点球/赛制更改后重新确认。项目导入亦重新确认结果以防误播。

队列优先级90/70/50/20，普通统计不打断事件，全屏互斥。紧急清屏立即取消延迟缓存和等待队列；计时继续。统一输出延迟作用于完整快照和服务时钟，不只延迟动画。

服务重启后临时动画与队列不恢复，避免旧事件重播；运行时钟停在最近检查点并明确询问是否补计离线时间，人工继续。正常异常边界见使用说明。

## 验证与实际边界

自动模型/服务测试覆盖时间戳与时长、补时、阶段、中断、账本幂等/取消/依赖、两黄和对象、多人换人、统计未知、总比分、点球、队列、延迟、紧急清屏、项目素材迁移、恢复和实际CMD中文路径启动。Edge浏览器生成两主题各26个1080p实际画面，操作验证预览不记账、记账播出、重复动画不加分、透明输出与清屏；记录在 design-previews/v1/validation.json。

另提供长中文名、缺队徽、逐线媒体和较长点球等回归场景；历史v0.2媒体验证仍保留。最终自动检查数量和结果以同目录验收记录为准，不用静态截图代替功能测试。

动画按1080p60设计，但本轮未在OBS持续推流中测FPS、CPU/GPU、内存及设备特定视频解码。目标设备应按整场验收表走一遍。浏览器自动播放策略可能使可选提示音不发声。导出大视频会增加JSON包与内存，实际移机可停服复制runtime。硬盘写失败或异常断电后应核对最近日志、时钟和操作结果。

## v1.1 比分牌修订（2026-10-19）

比分牌主计时器固定显示实际累计比赛时间，例如92:16；右侧补时块仅显示+n分钟，不再在下方显示宣布值/实际补时。后台的兼容补时格式只影响后台读数。进球、黄牌、红牌播出时，仅在对应球队下方展开事件与球员信息，退场收起。其他事件不占此扩展；总比分和点球辅助数值移至顶部小标签。

## v1.1.1 修正（2026-10-19）

红牌标记移至对应球队计分板上沿，不依附logo；完整牌高26px，裁切容器高13px，仅露半张，最多4张。后台手动校正和自动处罚逻辑均保留。

|---|---|---|
| 上半场，45分钟 | 00:45 | 1′ |
| 上半场，45分钟 | 45:21 | 45+1′ |
| 下半场，45分钟 | 45:21 | 46′ |
| 下半场，45分钟 | 91:21 | 90+2′ |

已有日志中手动保存的时间不自动重写，纠错可在日志操作。26项自动测试通过，含分钟边界、自定义时长、超补时、运行中全场播出拦截和队列清理；6组本次浏览器验证通过，材料在 design-previews/v1.1.1。

## v1.2.0 按比赛流程重组后台

按用户“主要在赛中操作”的要求，后台分为六类，默认赛中。赛前准备收纳队名/队徽/赛事资料、首发替补与翻牌、同步阵容、人物/裁判/赞助、两回合规则和开场顺播。赛中只常显小型真实输出监看、计时/补时、实际比分校正、事件与日志，队列、手动图文及统计折叠。中场提供半场流程、半场/下半场开球简版比分与统计；加时与点球保留逐轮记账和纠错；赛后提供最终结果确认、全场流程与导出；系统设置放两主题、独立模块开关、位置/缩放、赛制、延迟、快捷键、音效与字体。

导航不触发阶段切换、停表或播出。监看默认使用真实输出，可放大、可切回草稿预览，明确显示待播模块名称。赛中实际比分 ±1 记录 adjustment，可撤销，不伪造进球者或播放动画；独立草稿比分检查仍先存草稿。统计和项目存档控件跨相关分类复用同一节点，避免重复ID或表单丢值。保留根节点事件委托，名单上传、日志纠错、点球重罚和队列移除继续可用。

26项原有测试全部通过。新增19组实际Edge浏览器检查通过，含三种屏幕宽度、六分类无页面横向溢出、草稿隔离、客队进球、重播、红牌/换人、点球纠错及刷新。输出图形和服务端计时规则未因界面重组改版；本次测试使用临时数据目录，未向用户当前比赛写入测试事件。证据：design-previews/v1.2.0/validation.json，复现脚本 scripts/review-workflow.cjs。

## v1.3.0 计时与播出操作明确化

用户反映实播一直显示常驻。只读检查时源端和实际输出均为scoreboard、队列为空、最新进球已撤销；不是一个经过证实的“输出只能渲染常驻”的故障。此前默认待播模块也是常驻，模块选择藏在折叠区，且资料更新不会切换画面，容易误解。本版把选择画面和底部场景直接放到顶栏，明确区分仅预览、更新直播资料、播出所选画面和只显示左上比分牌，并提供常显提示与展开说明。实际浏览器验证可从常驻切换开场、底部比分和客队进球。

计时“切换阶段”和“开始/继续”合并为“应用”，服务端单次事务检测是否更改阶段：同阶段继续且不归零，变更比赛阶段采用自定义起点并开表，休息/结束阶段暂停；中断恢复遵循原阶段时间。计时清零须一次确认和服务端确认标记，清零并暂停，保留事件、比分、阶段与宣布补时。相对校准在服务端实际时间上增减并保留毫秒/运行状态，最低零，输入支持正负mm:ss；无符号仍是绝对设置。

“只显示左上比分牌”使用已发布资料而非新草稿，清空待播后切回常驻；F2同样使用该接口。比分与时钟不受影响，仍遵循统一输出延迟。紧急清屏仍立即生效。新接口需要重启服务，升级保留runtime与素材，并保持暂停供操作员核对。

30项Node测试、18组新增实际Edge浏览器检查通过，覆盖确认取消/确认执行、开表/同阶段继续/换阶段起点/休息暂停、绝对及负值校准、资料更新不重播、选择不误播、正式切开场、切回常驻清队列且不泄露草稿。证据：design-previews/v1.3.0/validation.json，脚本scripts/review-operator-controls.cjs。现有赛事分钟、自定义赛制、红牌、阵容、点球和两主题要求保留。

用户随后要求按赛前名单检索球员，本版一并实现。基于现有select数据源增强检索组件，按号码、姓名片段或位置过滤，鼠标/触摸与方向键/Enter选择后自动绑定姓名和号码。场上、替补给牌、换下、换上分别使用相应当前名单；换人后候选更新，原始首发保留。未重新选中匹配项时阻止旧球员被错误沿用；教练对象不强制检索球员。修正了替补给牌后切回进球仍沿用替补筛选的旧问题。相关界面和记账检查纳入18组浏览器验收。

## v1.3.1 特殊进球类型及乌龙球得分分离

按用户新要求，控件改名为特殊进球类型，只有普通/点球/乌龙三类。默认无（普通），普通进球的左下动画不渲染特殊标记；完成记账后恢复默认，避免特殊类型带到下一球。

原实现team含义是受益方，选择哪方即给哪方加分，与新的操作要求不符。新进球事件用team保存球员所属队，teamRole=player标识新语义；goalTeams独立计算得分方，乌龙时为对方。有效进球视图包含team与scoreTeam，播报、队伍扩展和记录按乌龙方展示；比分、取消、半场、总比分按得分方计算。编辑普通/点球/乌龙分类会同步重算。旧事件无标记时仍按原受益方语义保留得分，再推导球员所属方展示，避免旧档比分翻转。规范化、导出、导入保留新语义标识。

34项Node测试全部通过。新增11组实际浏览器检查覆盖双方乌龙、普通无特殊标记、预览不记账、重播不加分、取消同步、点球、本项目两主题、全场记录及新旧存档。证据design-previews/v1.3.1/validation.json，脚本scripts/review-own-goal.cjs。示例存档重新生成，主队许博文117′乌龙给客队加分，最终比分保持3:3。测试均在临时数据目录进行。

## v1.4.0 事件弹窗与整场包装修订

本版本汇总用户连续修订；PULSE、NOCTURNE与旧版标签均保留。赛中以8类事件入口替代常展开表单。点击事件弹窗按提示填写，点击“确认并预览”只生成模拟结果，确认预览后“应用并播出”才记账、更新比分/处罚并加入队列。修改输入会使确认失效；比赛账本修订变化时服务拒绝旧预览应用。预览等输出页准备好后才发送数据，避免首次载入丢失事件。计时与实际比分操作仍独立可用。

点球可选同时给牌，受罚球队独立于获得点球队。两项作为同一事务校验，失败不写入任何一项；重复提交幂等。记录保留两条关联事件以便单独纠错；播出只排点球，左下点球、左上对应队给牌，红牌同步常驻标记，重播不重复处罚。撤销关联给牌后重播点球不再显示该给牌。

进球无效改为左上对应队扩展：显示被取消球员、原进球时间与原因，原因可选四种预设或自行输入，取消同步本场/半场/总比分与所有进球记录。非比赛阶段不会常驻左上；主动播出进球无效时可短暂显示。所有输出的特殊进球统一(OG)/(P)，普通无标记，后台中文选项保持。乌龙仍归乌龙方球员、给对方加分。

VAR使用方框VAR字标，审核与决定独立状态；事项包含进球、疑似越位/犯规、点球、直红、第二黄导致离场、身份识别、其他事件，可继续添加选项。六类最终决定使用“VAR 决定 / VAR Decision”在左下播出。VAR决定仅为包装记录，实际进球取消/处罚纠错由操作员明确操作，避免一句审核文字隐式改写账本。

底部半场结束和下半场开场共用有效上半场比分及进球列表，后续进球不会混入，原记录纠错会同步。底部比分、点球、入场、事件、裁判和赞助统一先从自身中心横向展开，再向上展开，结束反向收拢；使用裁切动画保留居中定位，刷新按播出已过时间恢复。左上只在上/下半场及加时两个比赛阶段持续显示，手动暂停仍显示，休息、中断、结束和点球阶段隐藏；临时包装播完按阶段决定显示。不会因达到规定分钟或宣布补时而结束。
