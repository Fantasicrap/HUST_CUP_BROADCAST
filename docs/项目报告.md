# HUST_CUP_BROADCAST 项目报告

版本：v0.1.0-design-preview  
日期：2026 年 10 月 18 日（UTC+8）  
阶段：第一阶段视觉方案，等待用户确认  
最终目标：本地可运行、适配 OBS 浏览器源、单操作员完成整场比赛的中文足球直播包装系统。

## 1. 当前交付与进度边界

已完成项目命名、本地 Node.js 静态预览服务、中文视觉评审台、两套主题的六个关键画面及动画、原创赛事标识、两支示例球队与 11 人阵型数据、1920×1080 预览图片和预览版接入说明。

当前只有图形渲染与设计评审交互。示例时钟不会走动；点击重播不会加分。没有正式比赛数据管理服务、比赛状态机、数据库、播控队列、日志撤销、统一延迟或恢复机制。项目最终交付尚未完成，不能作为正式转播系统验收。

## 2. 两套视觉方案

PULSE「几何竞技」学习专业联赛包装的层级与紧凑信息组织，采用紫底、荧光黄绿色强调和米白信息面。NOCTURNE「蓝夜杯赛」学习杯赛的仪式感，以深蓝渐变、细光弧和冰蓝文字组织画面，开场赛事图形用浅金强调。全部图形为本项目自身素材。

| 规范 | 当前方案 |
| --- | --- |
| 输出画布 | 1920×1080，16:9 |
| 安全区 | 左右 96 px，上下 54 px |
| 比分牌 | 左上 x=96 / y=64，宽 652 px，主体约 175 px 高 |
| logo 布局 | 中央上层赛事 logo，两侧队名；下层比分集中显示 |
| 事件条 | 左下 x=96 / 距底 106，宽 1060 px |
| 大画面 | 开场、阵型独占画面，隐藏常驻和事件层 |
| 点球大面板 | x=300 / y=265，宽 1320 px，八轮样例 |
| 正文回退字体 | Segoe UI、Microsoft YaHei UI、Microsoft YaHei、Arial |
| 核心字号 | 比分 48 px，时间 32 px，事件姓名 44 px，阵型球员 25 px |
| 入场 | PULSE 460 ms，NOCTURNE 760 ms |
| 退场 | 320 ms；顺序预览每画面约 6 秒含入场 |
| 动画方式 | CSS transform / opacity 为主，不使用逐帧视频素材 |

当前评审页的“预览”不是正式版待播预览系统，它只改变本页 iframe，不会触发 OBS 另一地址中的播出。大画面互斥在当前示例通过一次只渲染一个场景实现；正式互斥仍需播控调度器。

## 4. 计划架构与关键约束

以下为实施方案，尚未实现。

本地服务维护单一权威比赛状态，通过 HTTP 命令接收后台操作，通过 SSE 或 WebSocket 推送带版本的状态。后台草稿、待播预览和实播状态分开保存。输出端仅渲染服务发来的正式状态，不读取编辑草稿。

比赛数据命令与图形播放命令分离。一次进球记账生成稳定事件 ID；播出与重播只引用该 ID，不重复写入比分。撤销进球将记录失效并统一重算比分、进球者、总比分和赛果卡。换人保存初始首发与当前场上名单，给牌记录明确区分场上、替补、教练。

计时使用 `elapsedAtAnchorMs + (serverNow - anchorServerMs)`，暂停时固化累计值。阶段、时钟与包装显示独立。阶段切换只由操作员明确操作，不因到时或进球而自动结束/暂停。宣布补时和实际补时分别保存，分钟事件标签另存。

持久化包含版本号、比赛数据、事件日志、计时锚点与输出设置。临时文件写入成功后原子替换。服务重启默认显示恢复确认，允许按时间戳补算或以保存时间暂停恢复，不应悄悄推进。输出刷新先获取当前快照与有效播出区间，过期动画不能重播。

正式输出延迟应在服务端统一安排 `effectiveAt`，比分、时钟锚点、红牌与图形事件都进入同一延迟时间线。禁止只对动画使用延时而提前更新比分。清屏提升播控代次、撤下当前图形并清空未播队列；旧代次事件全部失效。

大画面独占；进球、牌、换人等事件按优先级排队；统计不打断进球。恢复比分牌只恢复常驻层，不重播旧事件。点球大战独立数据域，判定条件只产生“可确认结果”，胜者发布必须经操作员确认。

## 5. 实施顺序

1. **视觉确认（当前）**：两套主题六关键画面确认与修改。
2. **播控基础**：本地状态服务、正式后台/输出分离、OBS 接入、时间戳计时、比分、阶段、统一延迟与恢复基础。
3. **事件与阵容**：数据命令与播出命令、日志纠错、给牌、取消进球、多人换人、队列、清屏、完整赛前流程。
4. **点球与淘汰赛**：独立点球状态、轮次算法、重罚纠错、两回合、半场/全场总结和人工赛果确认。
5. **完整主题与联调**：统计人物、转场角标、全部主题覆盖、导入导出、中文教程、整场演示、性能及恢复验收。
6. **GitHub 发布与报告定稿**：按用户最新要求，当前视觉预览版先上传；后续完整开发后继续更新仓库与报告。当前仓库为 `https://github.com/Fantasicrap/HUST_CUP_BROADCAST`，默认私有，两套主题一并保留，版本标签 `v0.1.0-preview`。最终报告仍需待全部功能验收后定稿。

## 6. 本阶段验证

使用本机 Edge 的无头浏览器渲染两套主题 12 个 1920×1080 画面；检查脚本语法、主题与场景切换、透明底开关、长中文名、安全区和扩展区。透明 PNG 的背景像素 alpha=0、信息条主体 alpha=255。检查中发现并修复比分牌入场裁剪遮住扩展区、缺徽替代文字过大两个问题。

`design-previews/validation.json` 保存浏览器验证记录。尚未执行 OBS 实机、推流、60fps 持续负载、真实数据记账、恢复及完整赛事验收。60fps 是设计目标，不是已测得性能承诺。

## 8. 用户约束与存档

5 小时额度剩余不超过 5% 时停止开发，保存代码、报告和下一步记录，次日由用户继续。当前暂停节点将优先依据用户指定的“先确认关键画面，再扩展全部组件”，不会在视觉未确认时擅自完成后续模块并称为交付。
