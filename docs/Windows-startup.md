# Windows 启动与闪退排查

v1.0 延续 v0.2.1 的启动修复；可双击「启动系统.cmd」或兼容旧名「启动预览.cmd」。

## 正常启动

1. 将压缩包**完整解压**到一个文件夹。不要在压缩包内部直接双击脚本。
2. 双击项目目录的 `启动预览.cmd`。
3. 等待窗口出现 `[READY] http://127.0.0.1:3210/`，随后自动打开浏览器。
4. 保持这个服务窗口打开；关闭它或按 Ctrl+C 后，网站会停止服务。

启动器优先使用 PATH 内的 Node.js；没有时，可使用当前电脑上已有的 Codex Node 运行时。两者都没有时，窗口会明确提示安装 Node.js 20+，并停留供查看，不会自动消失。

重复打开启动脚本时，如果同一个服务已在运行，会显示 `[ALREADY RUNNING]` 并打开已有页面，不会再启动一份服务写同一份存档。

## 不通过 cmd 脚本启动

在项目文件夹空白处右键「在终端中打开」，执行：

```powershell
node .\server.mjs
```

看到服务地址后，在浏览器打开 `http://127.0.0.1:3210/`。如果提示找不到 node，请先安装 Node.js，或使用已知的 Node 可执行文件路径运行 server.mjs。

## 显示错误时

- 窗口显示 Node.js 未找到：安装 Node.js 20 或更新版本后重新打开。
- 提示端口占用：检查原服务窗口是否仍在运行。也可以在终端执行 `$env:PORT='3211'; node .\server.mjs`，随后打开 3211 端口，OBS 地址也要相应修改。
- 没有自动打开浏览器：复制窗口内 `[READY]` 后的地址手动打开。
- 启动后又退出：查看窗口的具体错误，或项目目录的 `runtime\startup.log`。
- 实际出现 Windows 安全中心检测：保留检测名称和保护历史记录，用于进一步定位；本修复不会修改安全中心设置、添加排除项或解除文件保护标记。

## 本次已复现的问题

旧版启动文件包含中文与仅 LF 换行，本机 cmd 将部分内容错误解析为命令，输出“不是内部或外部命令”，导致服务未启动。当前启动器改为纯 ASCII 内容、CRLF 换行，并加了文件字节检查；Git 保存与压缩包均保留这些字节。

另外修正了原来的打开顺序：现在先确认本地健康检查成功，再打开网页，避免网页先打开而服务尚未就绪。失败时显示错误并保留窗口。没有修改任何杀毒或系统执行策略。
