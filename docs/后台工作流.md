# 后台工作流（v1.2）

后台默认进入“赛中”。左侧按比赛时间顺序分类，切换分类只查看相应工具，**不自动切换比赛阶段、不停表、不播出**。实际阶段仍在计时区选择并点击“切换阶段”。

| 分类 | 主要操作 |
| --- | --- |
| 赛前准备 | 新建比赛；球队、队徽、赛事logo；首发/替补/球衣/照片/视频；同步阵容；两回合规则；裁判、解说与鸣谢；开场顺播；导入项目 |
| 赛中（默认） | 实播监看、计时/补时、实际比分±1；进球、给牌、换人等；事件日志与撤销；展开查看待播队列、手动图文和统计 |
| 中场休息 | 半场流程、半场底部比分；统计；下半场开球底部比分 |
| 加时与点球 | 手动选择加时阶段；先罚队、罚进/失、逐轮纠错和重罚、确认结束；底部简版和结果大面板 |
| 赛后 | 人工确认胜者/晋级/冠军和最佳球员；全场流程/底部比分；统计；导出含素材存档 |
| 系统设置 | PULSE/NOCTURNE、各模块独立开关、停留时间、位置/缩放；赛制时长、统一延迟、快捷键、VAR/回放/音量、字体 |

## 赛中常用操作

1. 计时区选择阶段并切换，点击“开始 / 继续”。宣布补时只填 +n；超过宣布时长仍走时。
2. 选择事件和球队，再选择球员。时间留空会自动取比赛分钟。姓名、号码和所属半场的修正项默认收起，需要时展开。
3. “待播预览”不记账、不播出；“仅记账”更新比赛数据；“记账 + 加入播出”同时排队播动画。日志中的“重播动画”不会重复记账。
4. “比赛实际比分”旁 ±1 直接记一条比分校正，实际输出按统一延迟同步。它不增加进球者，可从日志撤销。正式进球请用进球事件录入。
5. 展开“待播队列与其他图文”，可移除待播、跳过当前、手动选模块、选择进球后重新开球等底部场景。普通统计不会打断正在播的进球。
6. “紧急清屏”取消当前、队列与延迟缓存，时钟保持原运行状态；“恢复左上比分牌”重新挂常驻。

## 监看与草稿

小监看默认显示真实 OBS 时间线，包括统一输出延迟。需要细看阵容或图文时点击“放大监看”。其下“预览模块与检查工具”收纳所有独立模块、透明底、安全框和长名称检查。

选择模块会进入草稿预览。“查看实际播出 / 返回待播预览”可切换；正式播出后会自动监看实播。“播出待播：模块名称”指示按钮将要播出的模块。编辑资料只存草稿，须点击“应用资料到实播”或正式播出才使用新资料。

系统设置里另有“草稿比分检查”，该处 ±1 不直接改比赛，需明确应用。与赛中实际比分校正分开使用。

## 半场与赛后

中场先由操作员暂停计时、切换比赛阶段，再播半场流程。下半场开场可直接点“播出下半场开球比分”，按配置5–6秒后恢复左上常驻；之后仍需自己切下半场并开表。

赛后先停表、核对比分和进球记录，再选择结果对象、称谓、勾选确认并保存。系统不会因为领先或时间到点而自动宣布结束、胜者或冠军。

统计表在赛中（默认折叠）、中场和赛后共用同一组输入，切换不会丢失未保存内容；点击保存才记入比赛。未知项目留空。导入/导出入口在赛前、赛后和系统设置，导入或新建前先备份。

## 更新与检查

运行中的本地服务直接读取前端文件，本次升级刷新控制页即可，OBS源地址不变；不要为界面更新导入演示存档覆盖正式比赛。原始比赛、事件账本、主题和模块均保留。

验收记录：`design-previews/v1.2.0/validation.json`；脚本：`scripts/review-workflow.cjs`。开发用浏览器测试另起临时服务，不向当前比赛写入测试事件。
